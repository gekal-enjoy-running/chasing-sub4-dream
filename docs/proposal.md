# 网站提案：Chasing Sub-4 Dream（全马破四追梦者）

## 1. 目的

记录一名业余跑者从「完赛」到「全程马拉松 4 小时以内（Sub-4）」的全过程，
把训练、比赛、配速和心得集中在一个自己掌控的网站上。

- **对自己**：把目标拆成看得见的数字（PB 与 3:59:59 的差距、目标配速），保持动力
- **对读者**：同样在冲击破四的跑者可以直接用配速表和计算器，并参考真实的训练与赛记

## 2. 目标读者

| 读者 | 想要的东西 |
| --- | --- |
| 我自己 | 进度可视化、训练日志、比赛复盘 |
| 准备破四的业余跑者 | 破四配速表、配速换算、训练计划示例 |
| 跑友 / 家人 | 下一场比赛是什么时候、最近状态如何 |

## 3. 网站结构

| 路径 | 页面 | 内容 |
| --- | --- | --- |
| `/` | 首页 | 破四进度（PB 与目标的差距）、下一场比赛倒计时、最新日志 |
| `/races/` | 比赛记录 | 全部比赛的成绩表 + PB 进步曲线（SVG） |
| `/races/[slug]/` | 赛记 | 单场比赛的成绩、分段、复盘 |
| `/journal/` | 训练日志 | 按时间倒序的训练记录 / 心得 |
| `/journal/[slug]/` | 日志详情 | Markdown 正文 |
| `/guides/` | 训练指南 | 跑前热身、跑后拉伸、力量训练、跑步技术练习、恢复与伤病预防 |
| `/guides/[slug]/` | 指南详情 | 每个主题的动作、次数、要点（Markdown） |
| `/pace/` | 配速工具 | 破四 5km 分段表 + 目标时间 ⇄ 配速计算器 |
| `/plan/` | 训练计划 | 16 周破四计划（基础期 → 强化期 → 巅峰期 → 减量期） |
| `/about/` | 关于 | 跑者介绍、跑步经历 |

## 4. 关键功能

1. **破四进度卡**：从比赛数据中自动计算全马 PB，显示距 4:00:00 还差多少秒、每公里还需快多少
2. **PB 进步曲线**：构建时用 SVG 绘制，不依赖图表库，零运行时 JS
3. **下一场比赛倒计时**：唯一需要浏览器端计算的部分（日期每天变化），做成小的客户端组件
4. **配速计算器**：输入目标时间 → 每公里配速、5km 分段、半程通过时间
5. **训练指南**：跑步之外的功课（热身 / 拉伸 / 力量 / 技术 / 恢复），用表格列出动作、次数和要点
6. **内容全部用 Markdown 管理**：新增训练日志或赛记只需在 `content/` 加一个文件并 push

## 5. 技术方案

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | Next.js 16 App Router + `output: 'export'` | 无服务器，纯静态 HTML |
| UI | MUI v9 + Emotion（`AppRouterCacheProvider`） | 组件齐全，CSS 变量配色自动跟随系统深色模式 |
| 内容 | `content/` 下的 Markdown（gray-matter + remark） | Git 管理，写作门槛低 |
| 测试 | `node:test`（时间换算、PB 计算、日期格式化） | 核心逻辑都是纯函数 |
| 发布 | GitHub Actions → GitHub Pages | push 即发布 |
| 域名 | `chasing-sub4-dream.gekal.cn`（自定义域名，根路径发布，无需 basePath） | |

静态化的判断：内容只在写日志/比赛后更新，每次重新构建完全可以接受；
没有登录、评论、表单等需要服务器的功能。

## 7. 发布前需要准备

1. DNS：为 `chasing-sub4-dream.gekal.cn` 添加 CNAME 记录 → `gekal-enjoy-running.github.io`
2. GitHub 仓库 Settings → Pages → Source 选择 **GitHub Actions**，Custom domain 填写上述域名并启用 HTTPS
3. 仓库目前是 **Private**：私有仓库使用 GitHub Pages 需要付费计划（Team / Enterprise），否则需改为 Public
4. 把示例数据（`content/races/`、`content/posts/`、`src/config/site.ts` 中的个人信息）替换为真实内容
